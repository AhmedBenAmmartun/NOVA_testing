# ProjectState v1 Schema

`ProjectState` is generated by `nova_intelligence.project_state.ProjectStateBuilder`.
It is never an authoritative hand-edited file.

## Top-level fields

- `schema_version`
- `project_id`
- `generated_at`
- `identity`
- `repository`
- `active_work`
- `systems`
- `issues`
- `decisions`
- `tests`
- `failed_approaches`
- `continuity`
- `conflicts`

## Fact envelope

Material scalar/structured facts use the `Fact` envelope:

```json
{
  "key": "git_head",
  "value": "...",
  "status": "VERIFIED",
  "freshness": "fresh",
  "confidence": 1.0,
  "note": "",
  "provenance": [
    {
      "source_kind": "git",
      "source": "git rev-parse HEAD",
      "observed_at": "...",
      "digest": "...",
      "note": ""
    }
  ]
}
```

## Status values

- `VERIFIED` — directly observed from the claimed source.
- `DERIVED` — deterministic interpretation of verified evidence.
- `UNKNOWN` — evidence is missing or insufficient.
- `STALE` — evidence existed but is outside its freshness window or no longer
  matches the current state.
- `CONFLICT` — incompatible evidence was observed and cannot be safely
  reconciled automatically.

UNKNOWN is a valid safe result. It must not be silently upgraded by guessing.

## Repository fields

A1 currently derives:

- branch
- HEAD commit
- dirty flag
- changed-file list
- local `testing` remote URL

The remote URL read is local Git configuration only. ProjectState does not make
a network call.

## Capabilities

Capability identity is parsed from the canonical
`nova_os/capability_definitions.py` source rather than duplicated in A1.

Recorded static fields are:

- capability_id
- name
- risk
- default_active
- locked_active

Runtime activation health is not inferred from static definitions. If runtime
state is unavailable, A1 must not claim it.

## Tests

A1 reports trusted test evidence only when `NOVA_CORE_TEST_EVIDENCE` points to a
local JSON evidence file and that evidence:

- says the gates passed; and
- matches the current HEAD commit.

Otherwise test status is UNKNOWN or STALE.

## Conflicts

The initial conflict list is deliberately conservative. Examples:

- dirty working tree while checkpoint documentation may claim clean state;
- no trusted test evidence matching current HEAD.

Future A2 work may add richer conflict resolution, but A1 does not auto-fix
conflicts.
